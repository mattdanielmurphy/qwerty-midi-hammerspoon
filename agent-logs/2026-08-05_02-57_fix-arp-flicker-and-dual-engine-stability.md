# Arpeggiator Key Flickering & Dual-Engine Stability Fix

- **Arp Key Flickering Fix**: In `src/web/index.html`'s `renderHud(data)` loop, `el.classList.toggle("latched-key", !!k.latched)` was removing `latched-key` from Arp-held keys on line 3527 because `k.latched` is false for Arp notes, only to re-add `latched-key` on line 3548 when scanning `data.arpHeldNotes`. This created a 30 FPS strobe flickering effect. Fixed by computing `isLatched = !!k.latched || (data.arpHeldNotes && (!!data.arpHeldNotes[code] || ...))` upfront before calling `classList.toggle`. Added `window.updateArpPitches` in JS so `fastUpdateArp()` functions cleanly.
- **Dual-Engine Instability Fix**: In `src/arpeggiator.lua`, when one Arp engine (Top or Bottom row) released all held notes, it previously called `state.arpTimer:stop()`, inadvertently killing the Arp timer while the other row engine was still actively holding notes. Updated the engine stop criteria to verify that BOTH `state.arpEngineTop` AND `state.arpEngineBottom` have zero held notes before stopping `state.arpTimer`.
- **Bundled & Reloaded**: Synced HTML to `src/ui_html.lua` and `qwerty_midi.lua` via `bin/bundle_and_reload.sh`.
