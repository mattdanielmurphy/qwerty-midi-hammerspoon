# Repository Context & Domain Knowledge

## Project Overview & Monorepo Structure
`surface-studio-suite` (formerly `qwerty-midi-hammerspoon`) is a Bun workspace monorepo (`packages/*`) unifying multimodal MIDI performance surfaces with a shared music engine and spatial HUD:
- `packages/qwerty-midi/`: Modular QWERTY keyboard MIDI controller for Hammerspoon.
- `packages/nanokey-studio/`: Korg nanoKEY Studio hardware driver with CC #64 Sustain & native SysEx Scene dual hold-to-reveal macro layers, 8 rotary dials mapped to Korg Gadget defaults (Cutoff CC 20, Peak CC 21, Drive CC 22, Volume CC 23, Attack CC 24, Decay CC 25, Sustain CC 26, Release CC 27), KAOSS touchpad (X = CC 1, Y = CC 19), 8 velocity trigger pads pre-assigned to CCs (Row 1: 43, 48, 50, 49; Row 2: 36, 38, 42, 46), 25 chiclet keys with octave-folding real-time visualizer, and dynamic surface switcher.
  - **Hammerspoon `hs.midi` Note Schema**: Note callbacks must inspect `metadata.note` (not `metadata.noteNumber`).
  - **Hardware Blueprint & Button Layout**: Left section contains 8 Knobs over two 3-button groups (`Octave -/+`, `Sustain` [SUS]; `Touch Scale` [SCALE], `X-Y`, `Pitch / Mod` [P/M]); Center section contains full-height Kaoss touchpad; Right section contains 8 Pads over two 3-button groups (`Scene` [SCENE], `Shift / Tap` [SHIFT], `Arp` [ARP]; `Chord Pad` [CHORD], `Easy Scale` [EASY], `Scale Guide` [GUIDE]).
  - **Inert vs. Interactive Hardware Boundary**: Verified empirically via live Bluetooth packet sniffing (`bin/sniff`): internal firmware buttons (`Octave -/+`, `Touch Scale`, `X-Y`, `Pitch / Mod`, `Shift / Tap`, `Arp`, `Chord Pad`, `Easy Scale`, `Scale Guide`) do NOT emit MIDI or BLE packets over the air, either individually or in combinations. Their GPIO lines route strictly within the internal microcontroller DSP (controlling local LED illumination, arpeggiator clock, and note quantization). Only `Keys`, `Pads`, `Knobs`, `Sustain` (CC #25/64), and `Scene` (Native SysEx `4140407f`/`41404000`) transmit to the host. Internal functions remain styled as recessed and non-clickable (`.nk-btn-inert`, `pointer-events: none;`) in the HUD. Software detects internal state indirectly via note ranges and burst patterns. The calibration CLI `bin/sniff` remains available for hardware testing.
  - **Physical Keyboard Note Range**: 25 physical keys transmit on Channel 1 (`ch = 0`) spanning notes 48 to 72 (C3 to C5) at factory default, with middle C at note 60 (C4) and high C at note 72 (C5). Octave folding in the GUI maps into the 48..72 window.
  - **Pad vs Keyboard Channel Isolation**: Physical keys transmit Note On/Off on Channel 1 (`ch = 0`, notes 48..72). Pads are pre-assigned to hardware CCs on Channel 1 (Row 1: CC 43, 48, 50, 49; Row 2: CC 36, 38, 42, 46) OR note channels (Channel 10 GM drum standard or Channel 2). CC messages and Note messages use distinct MIDI status bytes, completely eliminating cross-trigger collisions on a single channel. Keyboard notes never trigger pad highlights, and pad hits never trigger keyboard keys.
  - **Korg Kontrol Editor Flashing**: Flashing custom scenes to the nanoKEY Studio hardware requires selecting `Communication -> Write Scene` from the top menu bar; writing global data alone will not persist pad CC assignments.
  - **Diatonic Pad Chords**: In default performance mode, pads query `harmony.getDiatonicPadChord(padIdx, state)` to trigger scale degree chords (I through VIII 8va) matching the currently selected root, scale/mode, and voicing (Triad, 7th, 9th, Power, Octaves) with dynamic HUD name updates.
  - **Dynamic Scale Guide & Hardware LED Synchronization**: Resolves the nanoKEY Studio hardware limitation where its internal MCU Scale Guide remains statically locked to factory key C. Software calculates dynamic in-scale pitches and degrees via `harmony.getScaleGuideInfo(root, scaleIdx, 48, 72)`. The HUD renders glowing root accents (`#ffd700`) and diatonic roman numerals (`I..vii°`) on the 25 chiclet keys with out-of-scale muting, while `nanokey.syncScaleGuideLeds` sends MIDI `Note-On` (vel 127) and `Note-Off` (vel 0) to the controller's CoreMIDI output endpoint on Channel 1 (48..72), dynamically driving physical key backlights on key/scale transpositions. Toggleable via `#nk-btn-scale-guide` (`GUIDE`) or verified via CLI `bin/test-nanokey-leds`.
  - **Preferences Window Invariant**: `settingsWebview` uses `wv:transparent(true)` and `wv:windowStyle({ "borderless", "resizable", "nonactivating" })` with corner grip & border dragging in HTML. `_G.activeWatchers.midiScrollTap` bypasses Mod/Vol interception when hovering `settingsWebview`, permitting native scrolling.
- `packages/music-engine/`: Core musical intelligence (harmony, scale quantizer, chord voicings, master clock, arpeggiator).
  - **Real-Time Input Quantizer (`quantizer.lua`)**: Microsecond-precision input quantization grid supporting musical divisions (`1/1`, `1/2`, `1/4`, `1/8`, `1/16`, `1/32`, `Off`) across physical chiclet keys, trigger pads, and QWERTY performance keys. Employs 12ms anticipation, 20ms late catch-up, and staccato minimum gate safety (60% step or min 60ms) to prevent dropped or hung notes.
- `packages/surface-hud/`: Framework-agnostic Vite/WebKit HUD with 30fps coalescing, Web Audio anti-suspension sentinels, and zero-transition hardware rasterization (`-webkit-font-smoothing: antialiased`, `backface-visibility: hidden`) to eliminate bilinear font blur and subpixel layout shifting during state updates.
- `packages/studio-suite/`: Master multi-controller orchestrator (QWERTY Ch 1 + nanoKEY Ch 2).
- `packages/dualsynth/`: Handheld software-defined MIDI groovebox & 3D studio environment using Sony PS5 DualSense (`GameController.framework`, virtual CoreMIDI endpoint, native SwiftUI HUD with light/dark appearance, 6-axis gyro tilt-to-ModWheel CC#1, CoreHaptics vibration, and built-in Chord/Latch/Arp engine).
  - **DualSense Motion & Rest Angle**: Bluetooth motion on macOS streams only via `motion.acceleration` (not `gravity`). Table rest is $a_y \approx +0.174$; ceiling tilt decreases $a_y$ towards $-1.0$.
  - **CoreHaptics Driver Invariant**: Rapid parallel `makeAdvancedPlayer` triggers cause error `-4810` and daemon teardown. Use discrete pulse grains (120ms) with `Date` throttling.
  - **Logic Pro CC #11**: MIDI CC #11 (Expression) acts as a gain multiplier; idle value must default to 127 to avoid muting instruments.
  - **Held-Chord Morphing**: Holding any chord face button allows D-Pad to dynamically alter, add on to (+8va, +Sub), or transpose harmonies in real time with automatic reversion upon release.
  - **DualSynth Sound & Track Surface**: Sound & Tracks is the default mode. L2 sends expression/cutoff (CC #11/#74) and R2 sends FX/reverb send (CC #91), both with `setModeSlopeFeedback`, to the selected QWERTY Track 1–4 MIDI channel. Hold Create + D-Pad to select Track 1 ← / 2 ↑ / 3 → / 4 ↓; hold Options + D-Pad to select Sound & Tracks ← / Chords ↑ / Melodic → / Drums ↓ immediately. Trigger release never selects a menu item.
  - **Zero-Latency IPC Sync**: DualSense and Hammerspoon sync bidirectionally without ports or sockets via macOS native `NSDistributedNotificationCenter` (`DistributedNotificationCenter.default()` in Swift and `hs.distributednotifications` in Lua), synchronizing musical key, scale, BPM, octave, and real-time played notes.

## Key Files
- `packages/keystep-interceptor/`: Arturia KeyStep 32 hardware driver & side-channel interceptor. Automatically embeds an authentic KeyStep 32 controller display (32 slim keys notes 41..72, pitch/mod touch strips, knobs, transports, octave badges) directly below the QWERTY HUD when a physical KeyStep is detected, dynamically expanding HUD height from 280px to 600px.
  - **Knob CC Mapping & Logic Learn**: Rate knob is inferred from the median of multi-pulse sliding spans ($S = 4..16$ pulses, ~200ms window) of incoming MIDI timing clock ticks (24 PPQN), dividing host runloop quantization jitter by $S$ (< 0.8% error, < 2 BPM) to deliver smooth, continuous, sub-BPM tracking across the entire 30..240 BPM range with fast $\alpha = 0.85$ slew on knob sweeps. It emits dedicated CC #107 over the full 0..127 range for Logic Learn without skipping steps (`RATE_CC_DEADBAND = 0`). It avoids CC #7 and Arturia Macro 2 (CC #17), so the Rate knob no longer changes plugin volume directly. The Rate/Vol knob and QWERTY engine's internal row volume support the full $0..127$ range (`maxVolumeCc = 127`). Stepped knobs (Mode and Time Div) use safe unreserved CCs (Mode: CC 102 discrete & CC 105 continuous $[0, 18, 36, 54, 73, 91, 109, 127]$; Time Div: CC 103 discrete & CC 106 continuous).
  - **Immediate State Recall & Sequence Analysis**: Immediately recalls last known knob positions on HUD summon via dual-layer caching (`hs.settings` in Lua and `localStorage` in WebKit). Automatically evaluates recent sequence events via `KeyStep.analyzeSequenceAndInferKnobs()`: infers Rate from sliding-window clock pulse frequency, Mode from sequence marker notes (C10..G10 / 120..127), and Time Division from inter-marker pulse intervals ($24, 16, 12, 8, 6, 4, 3, 2$ pulses). Manual playable keys are strictly excluded from sequence history, pulse calculation, and division inference, preventing human keypresses from altering the Time Div knob or corrupting sequencer timing. Swallows marker notes and forwards all played notes and CCs to CoreMIDI with bidirectional WebKit IPC.
  - **Modal Shift, Pitch Routing & Two-Control ADSR**: Physical KeyStep firmware Shift button and internal buttons do not emit host MIDI. Black-key holds select Cutoff (CC 74), Reverb (CC 91), Delay (CC 92), Release (CC 72), or ADSR stage selection. A♯/B♭ selects Attack, Decay, Sustain, and Release in sequence; the Mod strip edits the selected stage (preset defaults CC 24–27). The Mod and Pitch strips display the recalled value for the effective assignment. Pitch uses Hammerspoon's `pitchWheelChange` command and remains 14-bit pitch bend by default; with a function active it controls that function on the selected track channel. The former A♯/B♭ Mod-to-Volume assignment is removed; the dedicated Rate/Vol path remains separate. Multiple held black keys are tracked independently; the most recently pressed key takes priority until released.
  - **Panic Timer Invalidation**: Panic stops all track arp engines, clears pending quantized events, stops their quantize and delayed-gate timers, releases held KeyStep/QWERTY notes, then sends explicit note-offs and CC 123/120 across all channels. Quantizer callbacks capture a generation so callbacks from before panic cannot emit delayed note events.
  - **Harmonic Transposer White-Key Lock**: White keys (19 keys) are routed through `transposer.getTransposedPitch()`, locking 100% of played notes to the active scale, mode, and root selected in the QWERTY GUI. A persistent `heldWhiteKeys` registry tracks exact played vs output pitches to prevent hung notes upon key release. Toggleable via `#ks-scale-lock-badge` in the KeyStep brand bar.
- `archive/nanokey-studio/`: Preserved archive of the Korg nanoKEY Studio hardware driver, layouts, macros, BLE/USB sniffer tools, and LED tester binaries. Bundling preset `nanokey-studio` remains supported in `bin/hs-bundler`.
- `src/`: Legacy/active QWERTY Lua source (`config.lua`, `midi.lua`, `transposer.lua`, `arpeggiator.lua`, `hud.lua`, `controls.lua`, `ui_html.lua`).
- `bin/hs-bundler`: Multi-target Lua bundler supporting presets (`qwerty-midi`, `studio-suite`, `surface-hud`, `nanokey-studio`).
- `bin/bundle_and_reload.sh`: Trigger script executed by the Launch Agent watcher (`com.matt.agent.qwerty-midi-bundler`).
- `qwerty_midi.lua`: Auto-generated bundled file created by `bin/hs-bundler`.
- `install.sh`: Symlinks `qwerty_midi.lua` into `~/.hammerspoon/modules/qwerty_midi.lua`.

## Development Guidelines & Rules
- **Modular Development**: Edit files inside `src/` (Lua) or `src/web/index.html` (UI HTML/CSS/JS).
- **Watcher Daemon**: The `watch_src.sh` daemon watches `src/` for Lua changes and auto-reloads. `src/web/` is explicitly excluded from `watch_src.sh` so web edits don't trigger full Hammerspoon reloads.
- **Manual Reload Required for Lua**: After changing any Lua module in `src/`, run `bash /Users/matt/projects/qwerty-midi-hammerspoon/bin/bundle_and_reload.sh`.
- **Validate the Bundled Lua Before Reload**: Run `luac -p qwerty_midi.lua` after bundling. Bun tests do not parse the Lua runtime bundle and can pass while Hammerspoon rejects the module at load time.
- **Non-Negotiable Agent Completion Gate**: A code task is incomplete until its affected runtime is activated and observed (Lua/offline HUD: bundle, `luac -p qwerty_midi.lua`, reload Hammerspoon, then confirm the intended module loaded), its relevant Bun/targeted checks pass, and its task-owned changes are committed and pushed. Capture the Git baseline before edits; a dirty tree is never a reason to skip publication, nor permission to stage unrelated work. Stage only clean-baseline task paths or safely isolated task hunks. A failed check, reload, push, or ambiguous same-file ownership is a named blocker—not a successful handoff. Follow `skills/custom-skills/scope-and-verification/SKILL.md`.
- **Web UI HMR (No Reload Needed)**: Run `bun x vite` from the project root to start the dev server (`http://localhost:5173`). When running, `src/hud.lua` connects directly to Vite. Edits to `src/web/index.html` (CSS/JS/HTML) hot-reload instantly in the webview without touching Hammerspoon or destroying MIDI state!
- **UI Production Build**: Running `bin/bundle_and_reload.sh` automatically syncs `src/web/index.html` into `src/ui_html.lua` for offline production distribution.
- **HUD Layout & Controls**: 4-row webview layout (`number`, `upper`, `home`, `lower`) using Fraunces Google Font and dark neutral theme. Trackpad scroll supports Mod Wheel (normal) and Volume (Shift held).
- **Consolidated 8-Layer Key Matrix & Multi-Track Architecture**: Supports Base, Shift, Option, Shift+Opt, Ctrl, Shift+Ctrl, Ctrl+Opt, and Ctrl+Opt+Shift modifier layers. `J` drives degree-based scale transposition ($\pm 1, \pm 2, \pm 3$, near root up, near subtonic down). `K` and `L` toggle bottom row (Tracks 1⇄2) and top row (Tracks 3⇄4) routing across 4 distinct MIDI channels. `F` is strictly Octave + (`octaveUp`) across base and modifier layers (with `topVolUp` on Shift); loop locking and stopping are assigned to `B` (`lockLoop`/`lockAndSwap`) and `N` (`stopLoops`). Shift-pressing note keys functions strictly as an one-way Arp Bypass modifier when arp is ON and never triggers arpeggios when arp is OFF.
- **Track-Colored Controls**: Per-track control keys dynamically reflect their assigned track's color (`--assigned-track-color`, `--assigned-track-rgb`). Top-row controls resolve to active top track (Track 3 or 4), bottom-row controls resolve to active bottom track (Track 1 or 2), and track selectors resolve to their individual track colors with high-contrast text and border glow.
- **Graphical Performance Indicators**:
  - **88-Key Performance Piano Monitor (Footer)**: Compact A0–C8 (MIDI notes 21–108) visualizer displaying all currently playing notes in real time across QWERTY playing, KeyStep forwarding, and arpeggiators. Backed by an active voice ledger in `src/midi.lua` tracking channel/pitch/track with panic cleanup and per-track voice colors.
  - **Selected Chord Type Mini-Piano (Header)**: Header notification badge includes an interactive mini-piano visualizing component pitch classes of the selected chord type (and detected chords) with root note highlighted in active track color.
- **KeyStep Disconnected Lower-Row Reversion**: When KeyStep is disconnected, the lower row (Z..M, codes 6..44) automatically reverts to bottom-row note input (tracks 1/2 note triggers); when connected, it functions as hardware control keys. The Home row remains completely identical in both configurations.
- **Isolated Multi-Track Looping & Visual States**: Tracks 1..4 operate on dedicated MIDI channels (0..3) with isolated arpeggiator state (`heldNotes`, `targetHeldNotes`, `activeGateTimers`). Switching active tracks (`1`–`4`, keys `18`–`21`) isolates the keyboard visualizer exclusively to the active track while background tracks continue looping MIDI. Note keys dynamically reflect the active track's primary color (`#00e5ff` Neon Cyan, `#ff9100` Vibrant Amber, `#00e676` Emerald Green, `#d500f9` Electric Magenta), the HUD chassis uses neutral dark grayscale (`0, 0%, 18%`), and track buttons display live states (`.trk-selected`, `.trk-muted`, and `.trk-waveform` with 5-bar pulsing animations on `.trk-audio-active`).
- **Track State Telemetry & Subtle Aesthetics Invariant**: Visualizes 6 distinct track states across Keys 18–21 in any combination without visual interference: Active/Selected (`.trk-selected`), Muted (discrete red `[M]` badge `.trk-badge-m.active`), Soloed (discrete gold `[S]` badge `.trk-badge-s.active`), Audio Occurring (5-bar animated waveform `.trk-audio-active`), Human Keypress (tactile pad surface glow `.trk-human-active`), and Arp Stepping (rhythmic tempo border flash `.trk-arp-step`). Text badges for human keys or arp notes are strictly prohibited to maintain subtle, elegant aesthetics.
- **Row Split Isolation & 4 Independent Arpeggiators**: Tracks 1 & 2 are strictly isolated to the Bottom Row (Home & Lower rows; MIDI Ch 0 & 1), and Tracks 3 & 4 are strictly isolated to the Top Row (Upper row; MIDI Ch 2 & 3). Selecting a track on one row never changes the other row, and both rows can be played simultaneously across separate MIDI channels. Each track runs its own independent arpeggiator clock timer (`trk.timer`), rate, gate, and direction. Functional mute and solo dynamically silence held notes, sustained pitches, and arp gates on inaudible tracks via `arpeggiator.isTrackAudible(trkId)` and `syncTrackAudibility()`.
- **Track Button State Authority**: Track selection/mute/solo state is written only by the coalesced `renderHud` payload. `fastUpdateArp` is restricted to note-key arp classes, and `updateKeyState` ignores keys 18–21 so generic press/release rendering cannot overwrite selected-track visuals. Playback waveform telemetry is disabled until it has a reliable single source.
- **Modifier-Safe Track Card Layout**: Track selectors (1–4) keep a dedicated `track-card` class through every modifier layer: code at top-left, role name at top-right, short action centred, and M/S state controls bottom-right. The routing icon stays hidden on track cards. K/L/; are ordinary non-track controls, so their mapped actions remain visible. Do not let long modifier labels collide with code, role, or state zones.
- **Focused-Track Arp Rate**: The visible arp-rate selector is the active track's rate. Rate changes persist to `qwertyMidi_track{n}ArpRateIdx` and immediately replace only that track's clock timer; selecting a track restores its rate in the header.
- **Arp Timing Invariant**: Per-track gate timers are generation-guarded before emitting note-off, so a stale callback cannot terminate a later retrigger of the same pitch. Arp HUD updates are deferred and coalesced to keep synchronous WebKit evaluation off the MIDI/gate callback path.
- **Zero-Layout-Shift (ZLS) Invariant & Chord Display Isolation**: All dynamic UI badges, dropdowns, and editors across `#header` and `.row-controls` enforce strict immutable bounds (`width`, `min-width`, `max-width`, `box-sizing: border-box`, `flex-shrink: 0`, and `tabular-nums`) with `overflow: hidden` to prevent Cumulative Layout Shift (CLS) when labels, numbers, or states change. The header chord badge and mini-piano isolate Chord Mode state from live chord detection: when Chord Mode is disabled, idle state displays `—` with the mini-piano completely unlit, and live polyphonic playing illuminates detected chords; dormant chord mode presets (e.g. "Triad") never illuminate keys when Chord Mode is off.
- **Per-Track Settings (Octave, Volume, Attack, Decay) & Two-Control ADSR**: Tracks 1–4 independently store and persist `volume` (0..100%), `octaveOffset` (-3..+3), `attack` (0..127), and `decay` (0..127) in `hs.settings` (`qwertyMidi_track{1..4}{Volume,OctaveOffset,Attack,Decay}`). Standalone release controls are eliminated in favor of a full-range two-control ADSR model: Attack controls both CC 24 and CC 73; Decay controls CC 25, CC 26, CC 27, and CC 72 across the full envelope range. QWERTY keys 9 and 0 control `atkDown`/`atkUp` (Base) and `decDown`/`decUp` (Shift); KeyStep lower row `.` and `/` control `decDown`/`decUp` on Shift.
  - **Attack/Decay Track-Colored Binding & Spotlight**: Number row keys 9 (code 25) and 0 (code 29) dynamically resolve to `state.activeTrack` via `resolveAssignedTrackId()`, applying `--assigned-track-color` and `--assigned-track-rgb` across active base/shift layers (`.per-track-ctrl`). Adjustments target the keypads (`key-25`/`key-29`) and draw spotlight borders matching the selected track's palette.
- **Per-Track Arp Direction Ownership & Recall**: Tracks 1–4 independently own and persist `arpDirectionIdx` (Up, Down, Up/Down, Down/Up, Converge, Diverge, Random) in `hs.settings` (`qwertyMidi_track{1..4}ArpDirectionIdx`). Switching active tracks immediately restores its direction in the header dropdown (`#arp-dir-select`), while cycling or setting direction via keys or GUI updates `trk.arpDirectionIdx` directly so each track's arpeggiator executes its own assigned pattern.
- **Quantizer Legato Mode (Zero-Gap Anticipation Sustaining)**: Solves awkward silent gaps when input quantization delays a note-on event to align with the grid. If a new note is queued with `delay > 0`, the quantizer keeps currently sounding notes (and notes released within a release grace window) actively sounding on that MIDI channel until the exact moment the new note triggers on the beat. Same-pitch notes send note-off immediately prior to note-on for clean voice re-attack, while differing pitches crossfade with true legato continuity.
- **KeyStep Bottom-Track Control & Arp Step Visualization**: KeyStep strictly targets and controls the active bottom track (`state.bottomRowTrack` — Track 1 or Track 2) for note playback, volume knob adjustments, pitch bend, and mod strip envelope manipulation. The embedded KeyStep visualizer in the HUD (`#keystep-view`) illuminates playing arpeggiator notes in real time (`.ks-key-w.arp-step`, `.ks-key-b.arp-step`) synchronized with the bottom track's arpeggiator output.
- **DAW Mute & Solo Audio Cutoff (Logic Pro Integration)**:
  - **Immediate Audio Cutoff**: Muting a track (or inaudibility via another track being soloed) immediately silences the instrument and effects in Logic Pro by transmitting CC 120 (All Sound Off), CC 123 (All Notes Off), CC 64 (Damper Release = 0), CC 7 (Volume = 0), and CC 11 (Expression = 0) on that track's channel (`trk.channel`). This eliminates synth voice release tails, reverb/delay rings, and droning audio.
  - **Logic Pro Controller Assignments (CC 108 & 109)**: Dedicated controller assignment CCs are emitted on each track's MIDI channel (Ch 1..4): CC 108 (Track Mute: 127 = Mute, 0 = Unmute) and CC 109 (Track Solo: 127 = Solo, 0 = Unsolo). Users can bind these to Logic's track header Mute/Solo buttons with Logic Learn (`Cmd+L`).
  - **Arpeggiator Persistence on Mute/Unmute**: Muting silences gate timers and sounding notes but preserves `trk.heldNotes`, `trk.targetHeldNotes`, and background clock ticking in tempo. Notes struck while a track is muted enter `arpeggiator.arpAddNote` seamlessly, and unmuting restores CC 7 volume (`trk.volume`), CC 11 expression (127), and immediately sounds the running or newly queued arpeggiator pattern.
- **Selected Track Persistence Across Reloads**: Active track (`state.activeTrack`), bottom row track (`state.bottomRowTrack`), and top row track (`state.topRowTrack`) are persisted in `hs.settings` (`qwertyMidi_activeTrack`, etc.) and loaded on startup. Calling `controls.selectTrack()` saves settings immediately and restores track state on module boot and MIDI mode re-entry.
- **Default Smart Sustain ON & Reverse Tab Damping**: Tracks 1–4 default to Smart Sustain ON (`sustainMode = "smart"` persisted per track in `qwertyMidi_track{n}SustainMode`). Pressing `Tab` (Key 48) executes reverse sustain damping: it immediately silences/damps currently ringing sustained notes on the active track for silence, holding `Tab` acts as momentary damping where played notes release staccato without latching, and `Option+Tab` explicitly toggles sustain mode between `"smart"` and `"off"`.
- **Global Control Exceptions vs Track-Colored Controls**: When a track is selected, all controls switch to target that track and are themed predominantly in that track's color (`var(--assigned-track-color)` and `var(--assigned-track-rgb)` with glowing borders and luminous backgrounds). The ONLY controls that remain global exceptions affecting all tracks are Transpose +/- (J: 38, K: 40), Root +/- (H: 4, L: 37), Scale/Mode +/- (G: 5, ;: 41), and Random (S: 1). Hardcoded yellow (`#ffd700`) styling on Key 48 and control keys is completely eliminated.


## DAW & Logic Pro Multi-Channel Note Interruption Behavior
- **Logic Pro Track Routing Note**: In Logic Pro, when multiple MIDI channels (e.g. Channel 1 Top Row, Channel 2 Bottom Row, Channel 3 Arp) are routed to a single track/instrument synth, Logic Pro's internal voice engine sums incoming MIDI notes across channels per pitch voice. If the same pitch is played simultaneously on both Top and Bottom rows and then released on one row, Logic's synth voice terminates upon receiving the Note-Off command regardless of channel.
- **Workaround / Setup Recommendation**: To prevent overlapping pitch cutoffs across Top and Bottom rows or Arp, assign separate, distinct instrument tracks in Logic Pro targeting individual MIDI channels (e.g., Track 1 listening on Channel 1, Track 2 listening on Channel 2, Track 3 listening on Channel 3) rather than routing all channels to a single instrument instance.
